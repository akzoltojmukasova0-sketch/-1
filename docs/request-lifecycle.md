# Жизненный цикл запроса

**Сценарий UC3.** Менеджер по логистике запрашивает оценку эффективности завершённого маршрута № 17.

Цифры в таблице совпадают с жёлтыми кружками на схеме. Запрос проходит все уровни: React SPA, Guards, Controller, модуль Analytics, ORM и PostgreSQL.

| № | Шаг | Что происходит |
| --- | --- | --- |
| 1 | Действие пользователя | Менеджер открывает карточку маршрута № 17 и нажимает «Оценить маршрут». React вызывает `fetch()` с запросом `POST /api/routes/17/evaluation`. |
| 2 | DNS | Браузер определяет IP-адрес сервера `routescore.example` через DNS (если адреса нет в кэше). |
| 3 | Соединение (TCP/TLS) | Браузер устанавливает TCP-соединение и выполняет TLS-рукопожатие: дальше данные передаются в зашифрованном виде (HTTPS). |
| 4 | HTTP-запрос | `POST /api/routes/17/evaluation`. Заголовки: `Content-Type: application/json`, `Authorization: Bearer <JWT>`. Тело: `{"includeBreakdown": true}`. Идентификатор менеджера в запросе не передаётся: сервер берёт его из токена. |
| 5 | Приём запроса | Запрос принимает NestJS напрямую (в учебной версии без отдельного веб-сервера; в промышленной эксплуатации перед ним может стоять Nginx). |
| 6 | Обработка в backend | **Guard** проверяет подпись и срок JWT и роль («менеджер»). **Controller** проверяет DTO (`id` — целое число) и передаёт запрос в Service модуля **Analytics**. Analytics проверяет, что маршрут завершён, получает данные через модули **Routes** (маршрут, доставки, транспорт), **Tracking** (GPS-точки, фактический пробег) и **Reference** (нормативы и веса). Считает пять показателей и индекс, определяет категорию. Внешние сервисы в этом запросе не вызываются: плановые расстояние и время получены при создании маршрута (UC1), а GPS-точки накопились во время рейса (UC2). |
| 7 | Обращение к БД | Через Prisma: `SELECT` маршрута с транспортом (`routes`, `vehicles`); `SELECT` доставок маршрута по порядку (`deliveries`); `SELECT` GPS-точек маршрута по времени (`gps_tracks`); `SELECT` действующих нормативов (`kpi_rules`). После расчёта — `INSERT INTO efficiency_scores` (показатели, индекс, категория, снимок нормативов, `user_id` из токена). |
| 8 | Ответ | `201 Created`, `Content-Type: application/json`. Тело: `{"evaluationId": 305, "routeId": 17, "index": 78, "category": "средняя", "plannedKm": 118.4, "actualKm": 144.0, "metrics": {"onTimePct": 72, "pathEfficiencyPct": 82, "successPct": 96, "loadPct": 71, "costScore": 64}}`. Возможные ошибки: `401` (нет или неверный токен), `403` (недостаточно прав), `404` (маршрут не найден), `409` (маршрут ещё не завершён), `422` (недостаточно данных для расчёта). |
| 9 | Обновление интерфейса | React получает ответ, сохраняет оценку в состоянии и показывает карточку результата: индекс и категорию, пять показателей, сравнение «план — факт» по километрам и кнопку «Сформировать отчёт». |

## Проверка расчёта на примере

`0.35 × 72 + 0.25 × 82 + 0.20 × 96 + 0.10 × 71 + 0.10 × 64 = 25.2 + 20.5 + 19.2 + 7.1 + 6.4 = 78.4`, то есть индекс 78 (категория «средняя», диапазон 60–79). Эффективность пути: 118.4 / 144.0 × 100 ≈ 82.

## Как сервер узнаёт, кто отправил запрос

Сессий на сервере нет. Клиент присылает JWT в заголовке `Authorization`, Guard проверяет его подпись и срок действия и достаёт из токена идентификатор пользователя и роль. Поэтому запрос может обработать любой экземпляр backend.
